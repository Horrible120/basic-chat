# 多人聊天室机器人前后端对接说明

这份文档供前后端同学讨论接口使用；其中的事件结构是建议，尚未实现，也不是已经确定的协议。

## 当前状态

- 多人聊天室通过 `/ws?nickname=昵称` 连接，客户端发送 `chat` 消息，后端向在线成员广播。服务器重启或页面刷新后不会恢复历史记录。
- 前端支持在自己的消息里输入 `@机器人` 或 `@AI`。收到自己消息的广播后，前端会在当前浏览器生成模拟回复；其他成员看不到该模拟回复。
- 输入 `@机器人 搜索 Vue` 可看到模拟工具状态。模拟内容没有访问大模型或真实工具。
- 聊天界面和背景已更新；真实机器人、工具调用及完整浏览器联调尚未完成。

## 后端建议职责

1. 在接收到聊天消息后，由服务端统一识别机器人提及，并正常广播原消息。
2. 为每次请求创建唯一 ID，在后台异步调用模型；提供有界的聊天上下文和超时处理，避免阻塞其他用户聊天。
3. 如果模型需要调用工具，由后端校验参数、执行允许的工具，将结果交给模型继续生成；密钥只保存在后端。
4. 将机器人回复和需要公开展示的工具状态发送到同一聊天室；提供成功、失败或超时的结束状态，并避免重复触发。

## 待双方确认的事件格式

沿用现有 WebSocket 或采用其他方式均可；下面是基于 WebSocket 的讨论示例：

```json
{"type":"bot_start","requestId":"请求ID","replyTo":"原消息ID"}
{"type":"bot_delta","requestId":"请求ID","content":"回复增量"}
{"type":"tool_start","requestId":"请求ID","toolCallId":"工具调用ID","name":"工具名称"}
{"type":"tool_result","requestId":"请求ID","toolCallId":"工具调用ID","success":true,"summary":"可公开展示的结果"}
{"type":"bot_done","requestId":"请求ID"}
{"type":"bot_error","requestId":"请求ID","message":"机器人暂时无法回复"}
```

需要明确：消息关联和顺序、多用户同时 @、重连后行为、机器人上下文范围、哪些工具结果对所有人可见，以及错误、超时与取消的处理。不要在公开事件中包含密钥或其他敏感数据。

## 前端接入工作

- 在 `frontend/src/composables/useChat.js` 中移除只对发送者触发的 `respondLocally`，改为接收后端机器人事件；避免真实和模拟回复同时出现。
- 在 `frontend/src/App.vue` 中按约定显示机器人消息、工具执行中、结果和失败提示。当前展示只用于模拟，需要适配最终事件格式。
- `frontend/src/chatService.js` 是模拟逻辑，后端协议确定后再移除或改为可明确开启的演示模式。
- 联调至少覆盖：两个用户同时在线、两人都能看到同一机器人回复、连续或同时提问、工具成功和失败、连接中断，以及普通聊天不受影响。

## 现有验证

前端构建：`npm --prefix frontend run build`。模拟事件测试：`node --test frontend/tests/*.test.js`。这些检查不证明真实模型或工具已经接通。
